<threat_model>
## Threat Model

- **Ameaça:** API e web em produção rodarem commits diferentes.
  **Mitigação:** `docker-compose.dokploy.yml` builda `sinarca-api` e `sinarca-web` do mesmo commit.
- **Ameaça:** segredos vazarem no repositório.
  **Mitigação:** `.env.example` contém somente nomes/valores fictícios; docs mandam usar secrets do Dokploy/Supabase.
- **Ameaça:** frontend chamar API local em produção.
  **Mitigação:** `VITE_API_URL` documentado e Dockerfile frontend recebe build arg/env.
- **Ameaça:** deploy passar sem healthcheck real.
  **Mitigação:** healthcheck do serviço API usa `GET /health`; smoke externo documenta API e web.
- **Ameaça:** cutover parcial manter `backend/main.py` escondido como fallback.
  **Mitigação:** Dockerfile, compose, README e specs apontam somente para `backend_app.main:app`, e smoke de staging valida frontend consumindo `backend_app`.
</threat_model>

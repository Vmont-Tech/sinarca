<threat_model>
## Threat Model

- **Ameaça:** dados financeiros ou de token manipulados fora das regras de negócio.
  **Mitigação:** escrita de `ledger_entries`, `purchases`, `retirements`, `treasury_positions`, `yield_distributions` e `chain_events` restrita ao backend service role.
- **Ameaça:** usuário ler saldos/transações de outra organização ou mutar dados usando um cliente Supabase direto.
  **Mitigação:** RLS mínima sem dependência de Supabase Auth, leitura pública somente para visões públicas e mutações sensíveis apenas pelo backend/service role, com papéis validados pela auth própria.
- **Ameaça:** drift entre schema local e produção.
  **Mitigação:** migrations SQL versionadas e tarefa `[BLOCKING] supabase db push` real.
</threat_model>

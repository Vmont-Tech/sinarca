<threat_model>
## Threat Model

- **Ameaça:** quebra silenciosa do contrato `/api/v1` durante o rebuild.
  **Mitigação:** suíte `tests/contract/test_api_v1_contract.py` cobrindo rotas, payloads e shapes usados pelo frontend.
- **Ameaça:** bypass de auth/base URL por chamada direta para localhost.
  **Mitigação:** `RetireCredits.tsx` usa `apiPost`, herdando bearer token e `VITE_API_URL`.
- **Ameaça:** testes legados mascararem regressão por esperarem endpoints removidos.
  **Mitigação:** remover ou atualizar asserções para `financials` e `/api/v1/monetization`, que não existem no contrato atual.
</threat_model>

  <action>
    Criar `tests/contract/test_api_v1_contract.py` com `fastapi.testclient.TestClient` apontando para `backend.main:app`.

    A suíte deve cobrir, com payloads concretos:
    - `GET /health` retorna `{"status": "ok", "service": "sinarca-api", "version": "0.2.0-integrated"}`.
    - `POST /api/v1/auth/login` aceita `{ "email": "empresa@sinarca.com.br", "dadoLogin": "empresa@sinarca.com.br", "password": "empresa", "role": "company" }` e retorna `token`, `access_token`, `refresh_token`, `expires_at`, `expires_in_seconds` e `user.role == "company"`.
    - `POST /api/v1/auth/register` bloqueia `role: "admin"` com HTTP 400 e permite `role: "producer"` com HTTP 201.
    - `GET /api/v1/projects?limit=1000` retorna `success: true`, `total` numérico e `projects` como array.
    - `GET /api/v1/projects/{id}` retorna `project.id` igual ao ID solicitado.
    - `GET /api/v1/audit/queue` e `GET /api/v1/certifier/queue` retornam `success`, `total` e `projects`.
    - `PATCH /api/v1/certifier/projects/{projectId}/decision` aceita `APPROVE`, `REJECT`, `REQUEST_CHANGES` e retorna `new_status`.
    - `PATCH /api/v1/audit/verify/{projectId}` aceita `APPROVED`, `BLOCKED`, `RECALCULATED` e retorna `new_status`.
    - `GET /api/v1/marketplace` retorna `credits`.
    - `POST /api/v1/marketplace/buy` registra transação `PURCHASE` sem exigir wallet externa do comprador.
    - `POST /api/v1/marketplace/compensate` aceita `buyer_id`, `emissions_data`, `credits_to_use` e retorna `certificate`.
    - `POST /api/v1/inventory/upload` rejeita `content_type` fora de `ALLOWED_UPLOAD_CONTENT_TYPES` com HTTP 415.

    Cada teste deve resetar `USERS`, `PROJECTS` e `TRANSACTIONS` quando mutar estado para evitar poluição entre casos.
  </action>

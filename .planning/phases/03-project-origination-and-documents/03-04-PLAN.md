<threat_model>
## Threat Model

- **Ameaça:** arquivo local aparecer como persistido sem upload concluído.
  **Mitigação:** estados separados `local`, `uploading`, `uploaded`, `error`.
- **Ameaça:** usuário criar projeto sem inventário/documento obrigatório.
  **Mitigação:** revisão bloqueia enquanto tipos mínimos não estiverem `uploaded`.
- **Ameaça:** hash/documento sensível exposto demais.
  **Mitigação:** UI mostra hash truncado na criação e dossiê controla visibilidade pública.
</threat_model>

    Criar `src/services/projectDocuments.ts` exportando:
    - `type ProjectDocumentType = 'LEGAL_OWNERSHIP' | 'CAR' | 'FOREST_INVENTORY' | 'KML_OR_SHP' | 'OTHER'`;
    - `type UploadedProjectDocument = { id: string; projectId: string; documentType: string; filename: string; mimeType: string; sizeBytes: number; sha256: string; storagePath: string; status: string }`;
    - `uploadProjectDocument(projectId: string, documentType: ProjectDocumentType, file: File): Promise<UploadedProjectDocument>`.

    A função deve montar `FormData`, adicionar `document_type` e `file`, e chamar `apiPost` em `/projects/${projectId}/documents`.
  </action>

  </verify>
  <acceptance_criteria>
    - Não define manualmente `Content-Type`.
    - Usa `apiPost`, não `fetch` direto.
    - Tipo exportado cobre inventário florestal e documento legal.
  </acceptance_criteria>

<task id="T2" type="execute">
  <title>Adicionar estado e UI de anexos no wizard</title>
  <read_first>
    - `src/pages/Dashboard/AddProject.tsx`
    - `src/services/projectDocuments.ts`
    - `.planning/phases/03-project-origination-and-documents/03-UI-SPEC.md`
  </read_first>
  <action>
    Substituir a dropzone visual por:
    - `<input type="file">` acessível;
    - seletor de tipo do documento;
    - lista de anexos locais com nome/tamanho/tipo/status;
    - botões de remover item local/erro;
    - controles de upload/remover com alvo mínimo de 44px;
    - status por texto e ícone, não apenas cor;
    - mensagens de extensão/tamanho vindas da API;
    - regra de revisão: exige pelo menos um `LEGAL_OWNERSHIP` ou `CAR` e um `FOREST_INVENTORY` com status `uploaded`.

    Como o endpoint exige `projectId`, o fluxo deve:
    - permitir selecionar arquivos antes da criação como estado local;
    - após `apiPost('/projects')` bem-sucedido, fazer upload dos anexos pendentes para o projeto criado;
    - só mostrar sucesso final quando todos os obrigatórios estiverem enviados.
  </action>
  <verify>
    `rg -n "type=\\\"file\\\"|uploadProjectDocument|FOREST_INVENTORY|LEGAL_OWNERSHIP|uploaded" src/pages/Dashboard/AddProject.tsx && npm run lint && npm run build`
  </verify>
  <acceptance_criteria>
    - Dropzone decorativa antiga não é o único mecanismo de documento.
    - Sucesso final aguarda upload obrigatório.
    - Erro de upload não perde o projeto criado; a UI mostra o que falhou e como tentar novamente.
    - Erro de cada arquivo aparece na linha do arquivo e também no resumo da etapa quando bloquear avanço.
  </acceptance_criteria>
</task>

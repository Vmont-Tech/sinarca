- Cobre Checklist 3:

</coverage>

<threat_model>
## Threat Model

- **Ameaça:** usuário enviar projeto sem quatro tags.
  **Mitigação:** bloquear revisão/envio até os vértices A/B/C/D estarem completos.
- **Ameaça:** lat/lng inválidos ou vazios gerarem geofence falsa.
  **Mitigação:** validação local para lat `[-90, 90]`, lng `[-180, 180]` e CMAC/UID não vazios.
- **Ameaça:** dados fixos de estado/cidade permanecerem como se fossem entrada real.
  **Mitigação:** trocar dropdown fixo por campos editáveis de município/UF e usar coordenadas médias derivadas das tags.
</threat_model>

<task id="T1" type="execute">
  <title>Criar tipos e validadores de originação</title>
  <read_first>

    - `src/services/api.ts`

  <action>
    Criar `src/services/projectOrigination.ts` exportando:
    - `type VertexLabel = 'A' | 'B' | 'C' | 'D'`;
    - `type ProjectTagDraft = { vertex_label: VertexLabel; tag_uid: string; cmac: string; latitude: string; longitude: string; captureMode: 'manual' | 'web-nfc' }`;
    - `const REQUIRED_VERTICES: VertexLabel[] = ['A', 'B', 'C', 'D']`;
    - `validateTagDrafts(tags)` retornando `{ valid: boolean; errors: string[] }`;
    - `normalizeProjectTags(tags)` retornando payload com `latitude`/`longitude` numéricos;
    - `averageCoordinates(tags)` para `location.coordinates`.

    Validações obrigatórias:
    - exatamente quatro tags;
    - vértices A/B/C/D sem duplicidade;
    - `tag_uid` e `cmac` preenchidos;
    - latitude entre -90 e 90;
    - longitude entre -180 e 180.
  </action>
  <verify>
    `npm run build`
  </verify>
  <acceptance_criteria>
    - Arquivo exporta `REQUIRED_VERTICES`.
    - `normalizeProjectTags` devolve chaves `tag_uid`, `cmac`, `latitude`, `longitude`, `vertex_label`.
    - Não há dependência nova no `package.json`.
  </acceptance_criteria>
</task>

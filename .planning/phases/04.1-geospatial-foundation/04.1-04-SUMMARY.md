**`ProjectsService.boundary_item`/`public_boundary_item` serve the persisted `project_boundaries` polygon as GeoJSON via `ST_AsGeoJSON` in both the public dossier (minimized) and the certifier review (full, with area-divergence telemetry) -- unblocking plan 04.1-05's frontend switch away from client-side polygon recomputation.**

## JSON Shape Reference (for plan 04.1-05's frontend types)

### Public dossier (`GET /api/v1/projects/{id}/public-dossier` -> `payload.boundary`)

Minimized via `public_boundary_item`:

```json
{
  "declared": { "type": "Polygon", "coordinates": [[[lng, lat], [lng, lat], ..., [lng, lat]]] },
  "active": { "type": "Polygon", "coordinates": [[[lng, lat], ...]] },
  "declaredAreaHa": 486.1234,
  "declaredVertexCount": 4,
  "activeTier": "DECLARED"
}
```

`boundary` itself is `null` (not an error, HTTP 200) when the project has no `project_boundaries` row (e.g. no `project_tags` yet). `declared`/`active` are `null` individually if only one geometry column is populated. Ring is always closed (first coordinate pair repeated at the end); coordinate order is `[longitude, latitude]` -- GeoJSON/PostGIS convention, opposite of this repo's `(latitude, longitude)` tuple/column convention and opposite of Leaflet's `[lat, lng]` prop order. The frontend consumer (plan 04.1-05) must swap per-point when feeding Leaflet.

### Certifier review (`GET /api/v1/certifier/projects/{id}/review` -> `payload.boundary`)

Full internal view via `boundary_item`, same `declared`/`active` shape plus:

```json
{
  "declared": { "type": "Polygon", "coordinates": [[[lng, lat], ...]] },
  "active": { "type": "Polygon", "coordinates": [[[lng, lat], ...]] },
  "fieldVerified": null,
  "certified": null,
  "declaredAreaHa": 486.1234,
  "declaredVertexCount": 4,
  "declaredSource": "api_v1_project_write",
  "areaDivergencePct": 363.1234,
  "areaDivergenceFlagged": true,
  "activeTier": "DECLARED"
}
```

`fieldVerified`/`certified` are `null` in every project created so far (this phase does not populate those columns -- Phase 05.1 scope). `declaredSource` is `"api_v1_project_write"` for projects created/updated through the API, `"backfill_qtag_shoelace_v1"` for the migration-backfilled seed project (`PRC-2024-002`). `areaDivergencePct`/`areaDivergenceFlagged` come from D-GEO-02 (never blocking, always exposed).

## Decisions Made

- Minimization split follows the plan's locked decision verbatim: `boundary_item` (full) feeds the certifier review, `public_boundary_item` (minimized, drops `declaredSource` + both area-divergence fields) feeds the public dossier -- the fourth instance of this exact pattern in the codebase, after `certification_item`/`public_certification_item` and `document_item`/`public_document_item`.
- `boundary_item` stays a method on `ProjectsService` (needs `self.session`); `public_boundary_item` stays a pure module function operating on the already-fetched dict, so the public dossier never makes a second DB round trip for the same row.

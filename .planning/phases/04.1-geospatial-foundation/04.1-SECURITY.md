## Accepted Risks Log

These three threats carry disposition `accept` in the PLAN.md threat models. Recorded here per the audit's disposition-verification requirement (accept → entry must be present in this log to close).

1. **T-041-10 — `ST_IsValidReason()` content in HTTP 400 responses.** The reason string PostGIS returns (e.g. "Self-intersection at ...") describes only the topology of the polygon the *same caller* just submitted in the request body. No schema, table name, other users' data, or server internals are disclosed. Accepted as-is; no code change required.
2. **T-041-18 — Serializing a persisted polygon as GeoJSON has no independent response-size cap beyond the write-time vertex limit.** Mitigated transitively by `MAX_PROJECT_TAG_VERTICES = 500` (`backend_app/modules/projects/service.py:146`), enforced at every write path (`persist_project_boundary` → `_validate_ring_shape`), so no polygon larger than 500 vertices can ever exist in `project_boundaries` to be serialized. Accepted: no separate read-path cap implemented in this phase.
3. **T-041-22 — Frontend renders whatever vertex count the API returns, with no client-side re-cap.** Same transitive server-side bound as #2 above (max 500 vertices ever exist to be sent). Accepted: no additional client-side guard implemented in this phase.

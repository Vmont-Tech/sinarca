# Phase 04.1 Plan 02: Server-Side Geometry Construction, Validation, and Persistence Summary

**Backend now builds, validates (PostGIS ST_IsValid/ST_IsSimple + Python vertex checks), and persists project geometry into `project_boundaries` on every project create/update, replacing the old "recompute-on-render, never store" model.**

## Performance

- **Duration:** ~15 min
- **Completed:** 2026-08-15
- **Tasks:** 3/3
- **Files modified:** 2

## Accomplishments
- `_ordered_ring`/`_polygon_wkt` reuse the exact centroid + `atan2` ordering already used by `_polygon_area()` since Phase 3 -- no new ordering algorithm, satisfying GEOF-02's "no loss of area/vertices" constraint carried forward into this plan
- `_validate_ring_shape` (cheap, Python-only) rejects <4 vertices, >500 vertices (`MAX_PROJECT_TAG_VERTICES`), duplicate coordinates, and out-of-range lat/lng before any DB round trip
- `_validate_boundary_geometry` runs a single PostGIS round trip (`ST_IsValid`, `ST_IsValidReason`, `ST_IsSimple`, `ST_Area(::geography)`) and raises HTTP 400 pre-commit on invalid/self-intersecting geometry
- `persist_project_boundary` upserts `declared_boundary` + mirrored `active_boundary` (`active_boundary_tier = 'DECLARED'`, D-GEO-03) into `project_boundaries` inside the same transaction as `project_tags`, wired into both `create_project` (after the tag loop, before `PROJECT_CREATED` audit) and `update_project` (inside the `payload.tags is not None` block, after tags are rewritten)
- D-GEO-02 area-divergence: always computed via `_area_divergence_pct`, always persisted (`declared_area_divergence_pct`/`declared_area_divergence_flagged`), never blocks -- proven end-to-end by `test_area_divergence_is_flagged_but_not_blocking` (HTTP 201 with ~363% divergence flagged) and by the full pre-existing `tests/test_certifier_workbench.py` suite (11/11) passing unchanged against fixtures that carry that same divergence
- 8 new integration tests added on top of plan 04.1-01's 4, all passing against the live local PostGIS instance (12/12 total in `tests/test_project_boundaries.py`)
- Zero coordinate values interpolated into SQL text anywhere in the write path -- `grep -c 'ST_GeomFromText(f"'` returns 0, all geometry SQL uses bound parameters (`:wkt`, `:area_ha`, `:project_id`, etc.)

## Decisions Made
- D-GEO-02 (locked decision this plan implements, recorded verbatim per plan output spec): the declared-vs-calculated area divergence is always computed, always persisted, always exposed, and never blocks persistence in this phase. Threshold `BOUNDARY_AREA_DIVERGENCE_WARN_PCT = 10.0` (percent) is flag-only. Evidence: for the fixture rectangle (0.02 deg x 0.02 deg at latitude ~-10.1), `_area_from_tags()`'s bounding-box heuristic returns ~104.93 ha while `ST_Area(::geography)` returns ~486 ha -- a divergence of ~363%. Any blocking threshold would reject every project that exists today. Only topological failures (invalid, self-intersecting, duplicate vertices, <4 or >500 vertices) block with HTTP 400.
- HTTP test fixtures copied (not imported) from `tests/test_certifier_workbench.py` into `tests/test_project_boundaries.py`, since `tests/` has no `__init__.py` and `from tests.test_certifier_workbench import ...` does not resolve under this repo's pytest configuration -- this is the plan's own documented fallback, not a deviation.

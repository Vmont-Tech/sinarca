# Phase 04.2 Plan 02: Claim/Evidence Layer Summary

**`IntegrityService` now creates origination Claims and document-backed Evidence automatically at the four points where a project or its documents are written, exposes them through two org-scoped read routes, and proves it with 8 new HTTP contract tests — closing INTG-01 and INTG-02.**

- **Duration:** ~35 min (Tasks 1-2 completed by a background executor agent; that agent's session hit an API session limit mid-Task-3 after writing but not committing the new test file — the orchestrator resumed by running the pending verification commands directly and completing the commit/tracking steps)
- **Tasks:** 3
- **Files modified:** 8 (3 created, 5 modified)

## Accomplishments

- `IntegrityService.create_origination_claims`: on `POST /api/v1/projects`, creates exactly 2 Claims (land claim type derived from document presence per D-18, `RIGHT_TO_OPERATE`), both `status=DECLARED` with a low, server-computed `confidenceScore` (0-20) — never from client input.
- `IntegrityService.create_evidence_for_document`: on every document write (draft submit, direct upload, certifier certificate persistence), creates an `Evidence` row whose `hash` is `documents.sha256_hash` (never recomputed), `sourceType=SELF_DECLARED`, `validationMethod` capped to `HASH_INTEGRITY`/`STRUCTURAL_COMPLETENESS` (D-08). Repeated uploads of the same file/type are idempotent (no duplicate Evidence).
- `LEGAL_OWNERSHIP` document upload reconciles the existing `LAND_POSSESSION` claim row to `LAND_OWNERSHIP` in place (D-18) — does not create a second Claim.
- When the required document set for a Claim is structurally complete, its Evidence reaches `validationStatus=VERIFIED` via `STRUCTURAL_COMPLETENESS`, and the Claim advances to `EVIDENCE_VERIFIED` (`confidenceScore=60`) — the ceiling for this phase (independent verification is Phase 05.1).
- `GET /api/v1/projects/{id}/claims` and `GET /api/v1/projects/{id}/evidence`: new org-scoped routes reusing the same access guard as `boundary-overlaps`/`pendencies` — 401 with no token, 403 for a caller outside the owning organization.
- 4 hook points wired without touching unrelated behavior: `ProjectsService.create_project` (after `persist_project_boundary`), `submit_project_draft`, `upload_project_document`, and `CertifierService._persist_certificate`.
- 8 new HTTP contract tests in `tests/contract/test_backend_app_api_v1.py`, covering origination Claim creation, the client-supplied-status guard (INTG-01), document-upload Evidence with reused hash (INTG-02), upload idempotency, LEGAL_OWNERSHIP reconciliation, the EVIDENCE_VERIFIED transition, the org-scope 401/403 guard, and the D-08 validationMethod cap.

## Decisions Made

- Certification decision events do not invent a new `validationMethod` — the certificate PDF gets Evidence through the same document-upload hook as any other document (D-21).

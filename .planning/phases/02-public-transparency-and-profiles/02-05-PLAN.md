## Cobertura do checklist

- Cobre Checklist 2:
  - Login/cadastro via API própria Argon2/JWT.
  - Logout no painel.
  - Tela de cadastro por perfil: produtor, empresa, auditor e certificadora.
  - Edição completa de perfil persistida no banco: nome, telefone, organização, documento e avatar.
  - Estados de erro amigáveis: credencial inválida, e-mail já cadastrado, sessão expirada e API indisponível.
- Fora de escopo:
  - Fluxo administrativo para provisionar admin fica na Phase 9; nesta fase é obrigatório apenas garantir que admin não tenha cadastro público.
  - MFA, RBAC avançado e governança completa de privacidade ficam na Phase 10.
- Gate de dados:
  - Cadastro e perfil devem gravar/ler `/api/v1/auth/*`.
  - Avatar pode ser URL persistida ou upload real se já houver contrato; não usar imagem aleatória externa como dado do usuário.
- UAT obrigatório:
  - Registrar produtor, empresa, auditor e certificadora.
  - Editar perfil e recarregar sessão para confirmar persistência.
  - Validar mensagens de credencial inválida, e-mail duplicado, sessão expirada e API indisponível.
</coverage>

<threat_model>
## Threat Model

- **Ameaça:** cadastro público permitir `admin`.
  **Mitigação:** UI não oferece admin e backend continua normalizando/bloqueando role admin em cadastro público.
- **Ameaça:** erros técnicos vazarem detalhes internos.
  **Mitigação:** mapear status HTTP/conectividade para mensagens amigáveis.
- **Ameaça:** sessão expirada deixar usuário em estado quebrado.
  **Mitigação:** interceptar 401/expiração, limpar sessão e orientar novo login.
- **Ameaça:** avatar/documento parecerem persistidos mas ficarem locais.
  **Mitigação:** salvar via `PATCH /auth/me` ou mostrar bloqueio explícito se upload estiver fora do contrato.
- **Ameaça:** termos/privacidade no cadastro abrirem alert em vez de páginas reais.
  **Mitigação:** linkar para `/termos` e `/privacidade`.
</threat_model>
